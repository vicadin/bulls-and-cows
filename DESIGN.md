# DESIGN.md - Bulls and Cows Architecture

## 1. Структуры данных и алгоритмы

- **Состояние игры (`GameState`)**: Неизменяемый объект (`readonly` поля). Обновляется возвратом нового объекта без мутации предыдущего (`submitGuess` в `src/core/state.ts`).
- **История попыток (`readonly HistoryEntry[]`)**: Массив записей попыток. Пополняется через `[...history, newEntry]`. Не использует `push()`, что исключает мутацию и обеспечивает предсказуемость истории. Дубликаты отсекаются через `history.some()`.
- **Алгоритм `evaluateGuess` (`src/core/evaluator.ts`)**: Приводит строки к `toLowerCase` и обходит символы попытки через `reduce`. Если символ равен символу секрета на той же позиции - инкрементирует `bulls`. Если присутствует на другой позиции (`includes`) - `cows`. Реализован без ручных циклов и мутируемых счётчиков.
- **Алгоритм `countPossibleSecrets` (`src/core/math.ts`)**: Рекурсивно вычисляет число перестановок $P(\text{radix}, \text{length}) = \text{radix} \times P(\text{radix} - 1, \text{length} - 1)$ с базовым случаем $P(\text{radix}, 0) = 1$. Обернут в функцию высшего порядка `memoize`, кэширующую результат в `Map` по ключу `"${length}:${radix}"` для мгновенных повторных вызовов.

## 2. Сложность алгоритмов (Big O)

| Функция                    | Time                             | Space                    | Обоснование                                                                                                                |
| :------------------------- | :------------------------------- | :----------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| **`generateSecret`**       | $O(L \times B)$                  | $O(B)$                   | $L$ - длина (2–6), $B$ - алфавит (2–16). Делает $L$ шагов рекурсии, на каждом фильтрует оставшийся массив размера $\le B$. |
| **`evaluateGuess`**        | $O(L)$ (или $O(L^2)$)            | $O(L)$                   | $L$ - длина строки ($\le 6$). Метод `reduce` выполняет $L$ итераций с проверкой равенства и вхождения символа.             |
| **`isValidGuess`**         | $O(L)$                           | $O(L)$                   | Проверка $L$ символов через предикат ($O(1)$ на символ) и проверка уникальности через `Set` размера $L$.                   |
| **`countPossibleSecrets`** | $O(L)$ без кэша / $O(1)$ с кэшем | $O(L)$ стек / $O(1)$ кэш | Глубина рекурсии равна $L$. После первого вычисления значение возвращается из `Map` за $O(1)$.                             |

## 3. Принципы Clean Code

- **Single Responsibility (SRP)**: Валидация вынесена в `src/core/validator.ts`, математика - в `src/core/math.ts`, оценка быков/коров - в `src/core/evaluator.ts`, генерация - в `src/core/generator.ts`, состояние - в `src/core/state.ts`.
- **Pure Functions & Immutability**: Все функции ядра в `src/core/*` чистые, не имеют побочных эффектов, не зависят от DOM. История обновляется через спред `[...history, entry]`.
- **Dependency Injection**: Функция `generateSecret` (`src/core/generator.ts`) принимает `random = Math.random` параметром, что позволяет тестировать её детерминированно.
- **HOF & Currying**: Фабрика `createDigitValidator` (`src/core/validator.ts`) возвращает каррированный предикат, переиспользуемый в валидации попытки и фильтрации ввода. Функция `memoize` (`src/core/math.ts`) - чистый HOF для мемоизации.
- **Declarative Style**: В `evaluateGuess` (`src/core/evaluator.ts`) вместо циклов `for` со счётчиками используется декларативный `reduce`.
- **Meaningful Names & Types**: Строгая типизация через TypeScript (`types.ts`), отсутствие магических чисел и сокращений.
- **Defensive Programming**: Проверка границ и нормализация систем счисления в `normalizeBase` и безопасная работа с `localStorage` через `try/catch`.
